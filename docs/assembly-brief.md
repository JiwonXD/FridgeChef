# 냉털 셰프 조립 요리 개편 작업 지시문

2026-11-07

## 요약

처음 요청은 "레시피를 많이 모아 넣고 조립 UI를 붙인다"였습니다. 전문가라면 레시피 원본에서 통계로 규칙을 뽑고, 만든 사람이 보지 않은 자료로 규칙을 검증합니다. 이 문서는 그 방향으로 다시 쓴 지시문이며, 아래 수치는 AICA_HRD에서 원본을 실제로 내려받아 확인한 값입니다.

가장 큰 발견은 기존 데이터 문제입니다. 손으로 쓴 궁합 340쌍을 레시피 769건과 대조하니 근거가 있는 쌍은 173쌍(51%)뿐이고, 75쌍은 한 번도 같이 나오지 않았고, 33쌍은 우연보다 덜 같이 나왔습니다. 말뭉치가 작고 재료 매칭이 단순 문자열 비교라 아직 초벌 결과지만, 데이터를 늘리기 전에 감사부터 해야 한다는 근거로는 충분합니다.

## 1. 최고 전문가라면 요청받지 않아도 할 일

- **기존 데이터 감사.** 궁합 340쌍, 나쁜 궁합 18쌍, 재료별 조리 시간 창을 원본과 대조해 고치거나 근거 없음으로 표시합니다.
- **근거 추적.** 모든 레시피와 궁합에 출처 ID를 붙여 "왜 이 점수인가"를 원본까지 거슬러 갈 수 있게 합니다.
- **라이선스 정리.** 한식진흥원 아카이브 레시피(7,796행)는 공공누리 제4유형(상업 금지, 변경 금지)이라 게임 데이터로 가공할 수 없어 제외합니다. 나머지는 출처 표기 파일을 build/licenses에 넣습니다.
- **맛으로만 판정.** 박지원 님 결정으로 안전 규칙은 뺐습니다. 덜 익히거나 날것이면 맛 점수만 깎입니다.
- **도달 가능성 보장.** 냉장고 18칸 무작위 구성에서 만들 수 있는 요리가 없는 판이 나오면 레시피 수가 무의미합니다. 냉장고 생성에 최소 요리 수 조건을 겁니다.
- **재료 공백 메우기.** 레시피 빈도 상위인데 게임에 없는 재료(무, 당면, 미역 등)를 통계로 찾아 우선순위를 냅니다.
- **시간 예산 검증.** 게임 시간 30분 안에 실제로 완성 가능한 요리인지 시뮬레이션합니다.
- **테스트 복구.** test_parity는 현재 dry 키에서 죽고 멈춥니다. 조립 판정 회귀 테스트로 교체합니다.

민간 레시피 사이트 크롤링은 약관과 저작권 문제가 있어 쓰지 않습니다. 향 화합물 기반 궁합(FlavorDB 계열)도 주 근거로 쓰지 않습니다. Ahn 등(2011)이 동아시아 요리는 향 화합물을 공유하는 조합을 오히려 피하는 경향이 있다고 보고했기 때문에, 한식 중심인 이 게임에는 레시피 동시 출현 통계가 맞습니다.

## 3. 전문가의 방법론과 도구

1. **원본 고정.** 내려받은 파일을 해시와 함께 보관해 재현 가능하게 합니다. AICA_HRD에 Python이 없어 Node 스크립트로 tools/recipes/에 둡니다.
2. **구조화.** HWPX는 XML로 풀고, 줄글은 재료 줄과 조리 문장을 규칙으로 나눕니다. 조리 문장마다 동작, 재료, 시간, 불 세기를 뽑습니다.
3. **재료 정규화.** 원본 표기(쇠고기, 불고기감, 계란)를 게임 재료 ID로 잇는 별칭 사전을 만듭니다. 매칭률과 미매칭 목록을 매번 출력합니다.
4. **궁합 통계.** PMI에 최소 동시 출현 3회 조건을 겁니다. 표본이 적은 재료(아보카도, 망고는 현재 0건)는 틀렸다고 보지 않고 근거 없음으로 분리합니다.
5. **시간 창 보정.** 재료와 조리법별 시간 분포의 사분위 범위를 현재 창과 비교합니다. 표본 5개 미만이면 바꾸지 않습니다. 초벌 추출로 조리 시간 문장 219개를 찾았습니다.
6. **요리 온톨로지.** 요리를 재료 나열이 아니라 역할(주재료, 밥이나 면, 곁들임, 양념)과 구성 요소로 모델링합니다.
7. **사람 검수 대기열.** 통계는 후보만 냅니다. 게임에 들어가는 요리는 검수 목록을 통과한 것만, 출처와 함께 넣습니다.

## 4. 주관 없이 확인할 외부 검증

| 검증 | 방법 | 통과 기준 |
|---|---|---|
| 보류 자료 재현 | 정밀레시피 30건을 규칙 제작에서 빼 두고, 게임에 있는 재료로 그대로 재현 | 해당 요리 이름 인식 90% 이상, 점수 A 이상 |
| 오탐 | 근거 없는 무작위 조합 1,000개를 조립 | 정식 요리 이름을 붙이는 비율 5% 이하 |
| 시간 창 | 정밀레시피의 실측 시간이 게임 적정 창에 드는지 | 80% 이상, 벗어나면 목록화 |
| 궁합 재감사 | 수정 후 GOOD 전체를 다시 대조 | 근거 있음 또는 근거 없음 표시 100%, 음의 PMI 미해명 0 |
| 도달 가능성 | 냉장고 1만 판 시뮬레이션 | 모든 주제에서 만들 수 있는 요리 5개 이상 |
| 시간 예산 | 레시피별 최소 조작 시간 계산 | 게임 시간 30분 이내 |
| 사람 평가(선택) | 요리를 해 본 3명이 요리 이름과 판정 20개를 블라인드 평가 | 평가자 간 일치와 함께 보고 |

사람 평가만 직접 도움이 필요합니다. 나머지는 스크립트와 Godot 헤드리스 테스트로 돌리고 수치를 그대로 보고합니다.

## 5. 다시 쓴 작업 지시문

**목표.** 냉털 셰프의 "재료 골라 한 번에 제출"을 없애고, 손질과 조리를 거친 구성 요소를 접시에 조립하면 하나의 요리가 되는 구조로 바꾼다. 요리와 판정 근거는 1차 자료에서 도출하고 외부 자료로 검증한다.

**데이터 단계.** 2장의 자료를 3장 방법으로 처리한다. 결과물은 tools/recipes/의 재현 가능한 파이프라인, data.json의 새 키, 감사 보고서다. 인증키가 오면 같은 파이프라인에 식약처와 농식품부 자료를 더한다.

**데이터 구조.**

- `PARTS`: 구성 요소. 예 `{id:"galbijjim", n:"갈비찜", need:["ribs"], opt:["potato","carrot","mushroom"], sea:["soy","sugar"], m:["boil"], cut:{ribs:"B"}, role:"main", src:[...]}`
- `DISHES`: 조립 요리. 예 `{id:"galbijjim_set", n:"갈비찜 정식", parts:["galbijjim","rice"], opt:[...], src:[...]}`, `{n:"불고기덮밥", parts:["bulgogi","rice"]}`
- `SOURCES`: 출처 ID, 자료명, 원본 해시, 이용 조건

**게임 흐름.**

1. 같은 기구에서 함께 조리한 재료는 조리가 끝나면 한 덩어리 구성 요소가 된다. 갈비, 감자, 당근을 함께 끓이면 냄비째 "갈비찜" 한 개다.
2. 구성 요소는 주방 조리대에 그릇째 놓이고, 빈 접시로 옮기면 그 위에 실제로 쌓인다. 재료를 하나씩 고르지 않는다.
3. 접시 툴팁의 이름이 조립에 따라 바뀐다. 갈비찜만이면 "갈비찜", 밥을 더하면 "갈비찜 정식".
4. 제출 버튼을 누르면 확인 창이 뜨고, 확인하면 선반의 접시 전부가 제출된다. 재료 체크 선택은 삭제한다.
5. 결과 화면에서 접시별로 넘겨 본다.

**판정.** 배점(주제 30, 궁합 15, 손질 15, 조리법 15, 익힘 25)을 유지하고 접시 단위로 채점한다. 최종 점수는 접시 점수의 재료 수 가중 평균이다.

- 궁합: 구성 요소끼리의 PMI와 DISHES 일치도
- 손질: 레시피가 요구한 썰기와 실제 비교
- 조리법: 레시피의 조리법 일치
- 익힘: 재료별 적정 시간 창
- 남은 시간 보너스와 남긴 재료 감점은 판 전체에 한 번

**디자인 제약.** 가운뎃점 금지, 텍스트 최소, 아이콘과 툴팁, 카드 블록 금지, 하나의 실제 주방처럼.

**완료 기준.** 4장 표의 수치를 모두 보고하고 미달 항목은 원인과 함께 명시한다. 회귀 테스트 통과, autopilot 스크린샷 확인, build\FridgeChef.exe 재빌드, main push, 출처 표기 포함.

두 번째 재현 수치는 정답지 결과를 본 뒤 규칙을 고친 값이라 더 이상 눈가림이 아닙니다. 눈가림 수치는 첫 줄입니다. 정밀레시피 30건 중 16건은 게임에 핵심 재료(잡곡, 김, 순대, 당면 등)가 없어 재현할 수 없습니다. 남은 실패는 끓인 돼지고기나 콩나물을 국과 수육, 무침으로 구별하지 못하는 것입니다. 게임에 물 양 개념이 없어 양념으로만 구별합니다. 말뭉치에 근거가 없는 구성 요소는 5개(닭죽, 소고기죽, 식빵피자, 스무디, 요거트볼)이고, 정식과 백반은 말뭉치에 없는 이름입니다. 식약처와 농식품부 인증키가 있으면 이 부분을 다시 측정할 수 있습니다.
